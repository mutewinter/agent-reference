$ agent-reference

Your coding agents read the real source of your dependencies, at the exact versions in your lockfile.

view source

Why not node_modules?

node_modules holds only what a package chose to publish, which is usually build output. The tests, the examples, the CI config, the commit that explains the weird branch — none of it is there. An agent reading node_modules is reverse-engineering.

agent-reference checks out each package's repository at the exact commit that published your version, and verifies it: the package.json at that commit has to report the same name and version, so a v1.2.3 tag belonging to some other package in a monorepo never passes as yours.

What your agent runs

package  zod                    3.25.76  3.25.76  ready   -              ~/.agent-reference/src/github.com/colinhacks/zod/50606616c0d2/packages/zod
folder   api-docs               -        -        ready   documentation  ~/work/platform/docs

notes:
  api-docs: Source of truth for endpoint contracts

groups:
  documentation: Read all of these before writing docs
    folder:api-docs, folder:design-notes

Agents follow the paths. When something is not usable, status leads with problems: and next steps: instead — each problem stating the failure, the fix, and the exact JSON to add. Nothing is left as a dead end for the agent to guess at.

Set it up

Paste this into your coding agent. Step 2 refers to a skill — a small instruction file that agents like Claude Code, Cursor, or Codex load automatically; the open skills CLI installs the one bundled with agent-reference. 

Set up agent-reference in this repository:

1. Install the CLI: npm install -g agent-reference
2. Optional: npx skills add mutewinter/agent-reference
   If it fails or prompts, skip it - the CLI works without it.
3. Create agent-reference.json. Run `agent-reference schema` for the
   format. List the dependencies whose source I am most likely to need
   as {"packages": {"<name>": "installed"}}, plus any local folders
   worth referencing, and give each one a short description.
4. Run: agent-reference validate
   Then: agent-reference clone
   Then: agent-reference status - every reference should be ready.
   If not, follow the problems and next steps it prints. Never delete a
   reference to make status clean; ask me instead.
5. Commit agent-reference.json and agent-reference.lock.json.
6. Append to this repo's CLAUDE.md or AGENTS.md:
   "Run agent-reference status before reading dependency internals, and
   use the paths it reports instead of node_modules."

Step 6 matters: without it, smaller models tend not to reach for the tool at all.

One committed JSON file

You and your agents edit agent-reference.json directly. There are no commands for adding references.

{
  "packages": {
    "react": "installed",
    "prettier": "3.6.2"
  },
  "git": {
    "typescript": "github:microsoft/TypeScript#v5.9.2"
  },
  "folders": {
    "design-notes": "./references/design-notes",
    "api-docs": {
      "path": "../platform/docs",
      "description": "Source of truth for endpoint contracts",
      "groups": ["documentation"]
    }
  },
  "groups": {
    "documentation": "Read all of these before writing docs"
  }
}

"installed" tracks whatever version is in your lockfile. Git references pin any repo at a tag, branch, or commit. Any reference takes a description and can join groups, so "read the documentation references" becomes --group documentation. When a repository tags releases in a way no tool can guess, pin it by hand with "ref" and it wins over everything.

Where it lands

  • One machine-wide store at ~/.agent-reference, the same path on every platform, holding mirrors under git/ and checkouts under src/ keyed by commit, shared across every project like the pnpm store.
  • Your repo gets two small committed files: agent-reference.json and the generated agent-reference.lock.json, which records resolved repos and commits with no machine-specific paths.
  • Network access is exactly two things: the npm registry, and git clone of each declared repository.
  • The store is a cache. agent-reference store shows what has accumulated and --prune trims it; rm -rf ~/.agent-reference is always safe, and clone rebuilds.

Commands

commanddoes
statusEvery reference with its absolute path, plus problems and next steps. --json for scripts.
cloneMaterialize configured references into the store.
validateCheck agent-reference.json and report located errors.
schemaPrint the JSON Schema for the config file.
storeShow what the shared store holds and how big it is. --prune trims old checkouts.

Both status and clone take reference names (agent-reference status zod) or --group <name>.
