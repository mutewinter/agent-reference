$ agent-reference

Your coding agents read the real source of your dependencies, at the exact versions in your lockfile. One CLI that clones package, git, and folder references into a shared machine-wide store — nothing heavy lands in your repo.

view source

Why not just node_modules?

node_modules ships build output: minified bundles, flattened .d.ts files, no comments, no tests. An agent reading it is reverse-engineering.

agent-reference clones each package's repository at the exact commit that published the version in your lockfile — gitHead when the registry has it, matching release tags otherwise — so agents read the original TypeScript, the tests, and the commit history.

One command, absolute paths

$ agent-reference status

kind     name  current  cloned  status  path
-------  ----  -------  ------  ------  ------------------------------------------------------------------------
package  ms    2.1.3    2.1.3   ready   /home/you/.cache/agent-reference/worktrees/github.com/vercel/ms/07dc9e5b6e60
package  zod   4.4.3    4.4.3   ready   /home/you/.cache/agent-reference/worktrees/github.com/colinhacks/zod/f3c9ec03ba7a

Agents run this and follow the paths. Every row reports one of five states: ready (use the path), missing / stale / missing-worktree (fixed by agent-reference clone --non-interactive), or not-installed (the config names a package that left the lockfile — a human decision). Folder and git references show - in the version columns.

How it works

  • Reads exact installed versions from your lockfile — pnpm, npm, Bun, and Yarn.
  • Resolves each package's repository and publish commit from the npm registry; falls back to release tags, then the default branch, and records which one it used.
  • Network access is exactly two things: the npm registry, and git clone of each package's declared repository URL.
  • Everything lands in one machine-wide store (~/.cache/agent-reference) — bare repos plus worktrees keyed by commit, shared across all your projects like the pnpm store. Delete it anytime; clone rebuilds it.
  • Your repo gets two small root files, both committed — agent-reference.json (what to reference) and a generated agent-reference.lock.json (the resolved repos and commits, no machine-specific paths). Like package.json and its lockfile.
  • Re-cloning after a version bump replaces the manifest entry, so status always points at exactly one copy per reference.
  • Uninstall: npm uninstall -g agent-reference && rm -rf ~/.cache/agent-reference.

Set it up

Paste this into your coding agent. Step 2 refers to a skill — a small instruction file that agents like Claude Code, Cursor, or Codex load automatically; the open skills CLI installs the one bundled with agent-reference so your agent knows to run status first. 

Set up agent-reference in this repository:

1. Install the CLI: npm install -g agent-reference
   Not on npm yet? Install from source with this repo's package manager
   (e.g. pnpm add -D github:mutewinter/agent-reference) and prefix every
   agent-reference command below with its runner (pnpm exec / npx).
2. Optional: npx skills add mutewinter/agent-reference
   installs the agent-reference skill for this harness. If it fails or
   prompts, skip it - the CLI works without it.
3. Run: agent-reference list
   Pick the dependencies whose source I'm most likely to need, then:
   agent-reference init --package <name> (repeat --package per pick)
   agent-reference clone --non-interactive
4. Commit agent-reference.json and the generated agent-reference.lock.json.
5. Verify: agent-reference status - every reference should be ready.
   missing or stale? rerun agent-reference clone --non-interactive.
   not-installed? the config names a package that is not in the
   lockfile - ask me before changing anything.
6. Append to this repo's CLAUDE.md or AGENTS.md:
   "Run agent-reference status and read dependency source from the
   paths it reports instead of node_modules."

Or by hand:

npm install -g agent-reference
npx skills add mutewinter/agent-reference

Three steps for humans

  1. agent-reference init --package react --package zod — pick the dependencies agents should be able to read; writes agent-reference.json.
  2. agent-reference clone --non-interactive — checks each reference out at its publish commit, into the shared store.
  3. agent-reference status — agents run this and follow the paths. Commit the config and lockfile it generated.

One committed JSON file

Commit agent-reference.json to share references with every agent that touches the repo.

{
  "packages": {
    "react": "installed",
    "prettier": "3.6.2"
  },
  "git": {
    "typescript": "github:microsoft/TypeScript#v5.9.2"
  },
  "folders": {
    "design-notes": "./references/design-notes"
  }
}

"installed" tracks whatever version is in your lockfile. Git references pin any repo at a tag, branch, or commit. Use agent-reference.local.json for personal, uncommitted paths.
