$ agent-reference

Materialize package, git, and folder references for coding agents. Agents read the real source of your dependencies, at the exact versions in your lockfile, instead of guessing from config files or node_modules.

Install

Point your agent at it

Paste this into your agent — it installs the CLI, the skill, and sets up the repo:

Set up agent-reference in this repository:
1. Install the CLI: npm install -g agent-reference
2. Install the skill for this harness: npx skills add mutewinter/agent-reference
3. Run agent-reference init and select the dependencies whose source
   I am most likely to need, then run:
   agent-reference clone --non-interactive
4. Verify with agent-reference status: every reference should be ready.
   From now on, read dependency source from the paths that status
   reports instead of node_modules.

Or by hand:

npm install -g agent-reference
npx skills add mutewinter/agent-reference
Status

One command, absolute paths

$ agent-reference status

kind     name          current  cloned   status  path
-------  ------------  -------  -------  ------  --------------------------------------
package  react         18.2.0   18.2.0   ready   .agent-reference/packages/react/18.2.0
package  zod           4.4.3    4.4.3    ready   .agent-reference/packages/zod/4.4.3
git      typescript    -        -        ready   .agent-reference/git/typescript/main
folder   design-notes  -        -        ready   references/design-notes

Every ready row is an absolute path to inspectable source. If anything is missing or stale, one command fixes it: agent-reference clone --non-interactive.

Workflow

Three steps, then agents are on their own

  1. agent-reference init --package react --package zod — pick the dependencies agents should be able to read; writes agent-reference.json.
  2. agent-reference clone --non-interactive — checks out each reference at the exact published commit.
  3. agent-reference status — agents run this and follow the paths. That's it.
Config

One committed JSON file

Commit agent-reference.json to share references with every agent that touches the repo.

{
  "packages": {
    "react": "installed",
    "prettier": "3.6.2"
  },
  "git": {
    "typescript": "github:microsoft/TypeScript#main"
  },
  "folders": {
    "design-notes": "./references/design-notes"
  }
}

"installed" tracks the version in your lockfile. Use agent-reference.local.json for personal, uncommitted paths.

Internals

Exact versions, real git checkouts

  • Reads exact versions from your lockfile — pnpm, npm, Bun, and Yarn are supported.
  • Resolves each package's repository and publish commit (gitHead, then release tags) from the npm registry.
  • Clones once into a global bare-repository cache; projects get cheap git worktrees under .agent-reference/.
  • Re-cloning prunes superseded worktrees, so on-disk source always matches the lockfile.
  • Ships a bundled skill so agents know to run status first.
